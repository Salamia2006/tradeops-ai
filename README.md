# TradeOps AI · демо для GitHub Pages и серверный MVP

Оркестрационный слой для сопровождения ВЭД-сделки: цель клиента, документы, проверки, подтверждение, симуляция платежа, сверка результата и кейс отклонения.

**Демонстрационный продукт, без подключения к ВТБ и без реальных денежных операций.** Все стартовые компании и реквизиты вымышлены. Исходная идея реализована по материалам заявки пользователя. В репозиторий не включены личные скриншоты заявки.


## Открытое демо для жюри

В этом пакете есть **готовая сборка для GitHub Pages**: `docs/index.html`, `docs/assets/`, `docs/favicon.svg` и `docs/.nojekyll`. Она не зависит от ChatGPT и не требует входа посетителя.

Демонстрационные сценарии и проверки работают в браузере. Данные сохраняются только на устройстве посетителя в IndexedDB. Реальные банковские системы, LLM и OCR не подключены. Баннер на сайте явно указывает режим хранения.

Серверная версия с HTTP API и SQLite/D1 также сохранена в исходниках и запускается командой `npm run demo`. Обе версии используют одно ядро `lib/tradeops/engine.ts`. В сборке Pages меняется только адаптер вызовов и хранения.

### Публикация

1. Создать отдельный публичный репозиторий `tradeops-ai` в аккаунте GitHub.
2. Загрузить **содержимое** папки проекта в корень репозитория, сохранив вложенность `docs/assets/`.
3. Открыть Settings → Pages, выбрать Deploy from a branch, ветку `main` и папку `/docs`, нажать Save.
4. Дождаться завершения публикации и взять **фактический адрес**, показанный в Pages. В заявку вставляется этот адрес сайта, а не адрес репозитория.

Папка `docs` уже собрана — Node.js и GitHub Actions для первой публикации не нужны. При изменении исходников выполнить `npm run build:pages` и обновить файлы `docs` в репозитории.

### Проверка браузерной сборки локально

```bash
python3 -m http.server 8080 --directory docs
```

Открыть http://localhost:8080. Двойной щелчок по index.html не рекомендуется: браузеры ограничивают загрузку модулей через `file://`.

## Быстрый запуск серверной версии

Требуется Node.js 22.13+ (рекомендуется Node 22 LTS), Git не нужен. Интернет нужен для первоначальной установки пакетов. API-ключи, банковские учётные данные и аккаунт Cloudflare для локального демо не требуются.

В распакованной папке проекта:

```bash
npm install
npm run demo
```

Откройте **http://127.0.0.1:8787**. Команда собирает приложение, применяет локальные миграции и запускает сервер. Остановка: Ctrl+C. При следующих запусках достаточно `npm run demo`. Данные остаются в `.wrangler/state`.

Для воспроизводимой установки используйте приложенный `pnpm-lock.yaml`: `corepack pnpm install --frozen-lockfile`, затем `corepack pnpm demo`. Если Corepack не установлен, установите pnpm поддерживаемым для вашей ОС способом или используйте npm выше. Вариант с npm заново разрешает транзитивные зависимости и не столь строго воспроизводим.

## Что показать жюри за 3–5 минут

1. На главной нажмите **«Разобрать кейс»**. Инвойс — 380 000 CNY, зачисление — 378 500 CNY, разница — 1 500 CNY. Система предлагает гипотезу о комиссии и сохраняет незакрытое обязательство.
2. Откройте **«Документы»**: извлечённые поля имеют номера строк в источнике. Откройте **«История»**: видны подтверждение и последовательность действий.
3. Нажмите **«Передать в демо-очередь»**, затем **«Скачать кейс»**. JSON содержит документы, снимок реквизитов, расчёт, предполагаемую причину и историю.
4. Вернитесь в **«Обзор» → «Обычный платёж»**. Сохраните документы, проверьте их, подтвердите черновик, симулируйте отправку. В сверке выберите **«Зачислено полностью»**. Сделка получит статус «Расчёты сверены».
5. Попробуйте **«Ошибка в инвойсе»**. Несовпадение 380 000 / 382 000 блокирует подтверждение. Исправьте сумму на вкладке документов, сохраните и снова проверьте.
6. Откройте **«Архитектура MVP»**: работающие модули и будущие банковские адаптеры отделены явно.

Подробный сценарий и ответы на вопросы: [docs/DEMO_SCRIPT.md](docs/DEMO_SCRIPT.md).

## Что действительно работает

| Возможность | Реализация |
|---|---|
| Документы | Загрузка локальных UTF-8 TXT или вставка текста; исходники и поля сохраняются на сервере |
| Извлечение | Детерминированный parser `rules-v1`; ключи по строкам, русский/английский, ссылки на источник |
| Сверка | Сумма, валюта, получатель, счёт, BIC, контракт, срок, комиссии, цель клиента |
| Платёжный черновик | Создаётся только после успешной сверки; неполный пакет блокирует действие |
| Подтверждение | Сохраняется снимок реквизитов; изменение документов сбрасывает подтверждение |
| Платёж | Только имитация через `PaymentGateway`, без сетевого обращения к банку |
| Сверка результата | Точный расчёт в целых минимальных денежных единицах; недоплата, переплата, комиссии |
| Кейс | Контекст отклонения, гипотеза и следующие действия; демо-тикет и выгрузка JSON |
| Сохранение | SQLite локально / D1 на хостинге, проверка версии, идемпотентные команды |
| История | Действия и состояние сохраняются атомарно в одном агрегате сделки |

## Прозрачные ограничения

- «AI» — название продукта. LLM и OCR **не подключены**; генеративного анализа произвольного текста пока нет.
- Формат — структурированный TXT, не произвольный PDF, скан, DOCX или MT103. Примеры: `samples/`. Поддерживается один инвойс на полную сумму одного контракта.
- Банковский валютный контроль, AML/санкционные проверки, курсы, тарифы, реальная отправка, зачисление и банковские тикеты не интегрированы. Формат BIC проверяется, существование банка — нет.
- Все суммы в одной валюте. В MVP у CNY/USD/EUR/RUB/AED два десятичных разряда. Конверсия и частичные/многократные платежи не реализованы.
- Комиссия, равная недоплате, является гипотезой, не доказанной причиной. Система не списывает обязательство и не создаёт доплату автоматически.
- История хранится вместе со сделкой, это не защищённый от изменения банковский журнал. Для пилота нужны роли, SSO, отдельный аудит и требования ИБ.
- На хостинге пространство привязано к идентичности посетителя; локально — к HttpOnly cookie браузера. В версии GitHub Pages нет серверной изоляции: данные находятся в браузере каждого посетителя. Это демонстрационная изоляция, не банковская многопользовательская модель. Реальные документы сюда загружать не следует.
- Интеграционные интерфейсы в коде — наши проектные контракты, не официальные API ВТБ. Для внешних вызовов потребуется outbox и банковская идемпотентность.
- Экономический эффект не измерялся; числа о сокращении затрат и времени не заявляются.

## Проверки

```bash
npm test
npm run typecheck
npm run build:pages
npm run build
npm run test:integration
```

`npm test` проверяет существенные бизнес-инварианты: запрет отправки без подтверждения, отзыв подтверждения, расхождения, повтор команд, комиссии, источник полей и точную арифметику. `tests/api-smoke.mjs` проверяет HTTP-путь и сохранение; запуск после `npm run demo`: `node tests/api-smoke.mjs http://127.0.0.1:8787`.

## Устройство проекта

- `app/page.tsx`, `app/globals.css` — интерфейс клиента и представление кейсов.
- `app/api/deals/route.ts` — HTTP API, входная валидация, изоляция, optimistic locking.
- `lib/tradeops/engine.ts` — извлечение, правила, машина состояний, сверка.
- `lib/tradeops/adapters.ts` — работающие симуляторы и интерфейсы для будущих интеграций.
- `lib/tradeops/repository.ts`, `db/schema.ts`, `drizzle/` — хранение и миграции.
- `lib/tradeops/fixtures.ts` — три воспроизводимых примера.
- `docs/ARCHITECTURE.md`, `docs/API.md` — архитектура и контракт API.
- `docs/DEMO_SCRIPT.md`, `docs/PILOT_PLAN.md` — защита и проверка ценности на пилоте.

Стек: TypeScript, React, Vinext, Cloudflare Workers, D1/SQLite, Zod, Drizzle, Radix UI. Нативные компоненты React и HTTP API используют одно серверное ядро; клиент не может перескочить этап через прямой API-вызов.

## Размещение на GitHub

Создайте пустой репозиторий на GitHub и загрузите распакованные исходники через интерфейс GitHub или выполните:

```bash
git init
git add .
git commit -m "TradeOps AI functional MVP"
git branch -M main
git remote add origin YOUR_REPOSITORY_URL
git push -u origin main
```

`YOUR_REPOSITORY_URL` замените адресом собственного репозитория. В исходном архиве нет Git-истории, токенов, данных локальной базы и служебного идентификатора опубликованного сайта. Папки зависимостей и окружения исключены через `.gitignore`.
